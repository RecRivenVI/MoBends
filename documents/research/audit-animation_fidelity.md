# 原版动画保真审查

2026-10-20 调查。结论：不能把当前移植称为与 MoBends 1.2.2 完全等价。已经确认洞穴蜘蛛尺寸丢失、两个 1.x Target 的鱿鱼周期错误，以及游泳、披风、鱿鱼触手锚点和幼年几何的差异。普通动作的局部数学大体保留；这不等于完整渲染链或所有动态场景通过。本轮只审查，没有修复产品代码。

## 问题

用户需要知道动作是否忠实于原版，而不是是否符合移植版自己编写的测试。本审查以原版 MoBends 1.2.2、Minecraft 1.12.2 的源码和发行包为标准答案，参考端为 `26.3-neoforge`，其他 Target 仅检查差异文件。

本报告把“原版 MoBends 的自建模型”“该版本 Minecraft 的原生模型”和“移植版的适配模型”分开。新版原生外形不等于原版 MoBends 外形；继承来的缺陷也不是新增移植错误。没有原版依据的适配标为**自创**，不以“适配”一词默认其正确。

### 三层判定的边界

1. **数学**：分别编译并执行两侧真实动作体、四元数、平滑与向量代码；只替代所需实体和世界输入。使用真实 `HardAnimationLayer`，原版 Kotlin 跳跃体实际编译执行。记录每个部件的目标及平滑四元数、位置、偏移、根变换和手持物旋转。剑轨只比较发射与重置时机，不冒充几何或透明排序对拍。
2. **模型**：检查原版游戏二进制反编译结果、当前游戏原生源码和两侧 Mutator。原生类来源及哈希见 `model-source-provenance.json`、`additional-native-source-provenance.json`。单纯比对类名和字段名不足以证明语义一致。
3. **画面**：两个真正的游戏进程顺序运行，各用自己的隔离世界。1920×1080、FOV 70、时间 6000、晴天、石英地面与荧石顶，固定相机与实体位置；非玩家提供正面、侧面、45°。截图来自游戏 framebuffer，拼图只作相同像素区域裁切和排列，不重绘、重着色或缩放。

数学夹具每步 0.5 tick；普通样本覆盖 40 tick，剑和拳覆盖 80 tick、连击与结束窗口。有效结果见 `math-summary.json` 及其指向的 CSV。原生 `Mth` 与 `MathHelper` 的正余弦查表差异保留；公共 `atan2` 替身、无坐骑实体、非完整碰撞世界、没有执行完整狼 KUMO 控制器、没有完整 GPU 矩阵，是明确限制。原版 Kotlin 用现有编译器编译，不宣称与旧发行二进制逐位相同。

画面中的天空、材质、光照引擎、实体 ID 决定的僵尸动作变体和渲染时钟并不逐像素相同。因此静止代表图可以检查整体比例、层级和显著错位，不能据一张图证明动态相位一致。初次采集含死亡粒子，首轮玩家补拍又被遗留狼遮挡；这些夹具污染图均不作为产品问题证据。定位夹具原因后只重采受影响画面，最终有干净的十项玩家正面代表图，见 `Comparisons/player-index.json`。非玩家为固定世界相机；玩家使用两代原生第三人称前视，相机跟随语义不完全相同，不据此计算像素级世界高度差。

玩家补拍还遇到两个夹具边界：低帧率时截图可能晚于按键释放，首轮潜行状态因此不成立；开放水池的残留流体可能流回清空区域。修正为按键保持到实际截图、扩大清水范围后，仅重采潜行、入水和两项盔甲。原版逐图状态记录实际潜行、水下和 MoBends 根四元数；移植端记录 MCP 的使用物品、离地、速度与输入状态。未修改产品代码或实体物理以“做出”姿势。

原版安装的世界、模型和纹理资源可用；另有 14 个非画面资源（音频和 Realms 语言）未下载成功，`OriginalRuntime/provision.json` 如实记录资源安装不完整。自动实例静音，不将这次安装称为完整音频验收。

## 发现

### 按可见程度排列的差异

排序以普通玩家可见范围为主，同时明确证据强弱；“确定公式差异”不自动等于“确定当前画面有错”。

| 编号 | 差异与出处 | 可见程度、判定和证据 |
| --- | --- | --- |
| F-01 | 26.x 洞穴蜘蛛丢失 0.7 缩放。原版及 1.x 在 renderer 中缩放；26.x 改为烘焙网格缩放，自建 `SpiderMutator` 绕过该网格 | **已确认画面错误**：本应为普通蜘蛛约 70% 的模型变为接近普通蜘蛛大小，线性约放大 1.43 倍。`Comparisons/cave-spider.png` 三机位；`26.3-neoforge-cave-layer.txt`；R `standard/mutators/SpiderMutator.java:59`。26.1.2 和 Fabric 为源码确认受影响，未外推为其运行 PASS |
| F-02 | 两个 1.x `SquidController` 用身体俯仰角 `xBodyRotO/xBodyRot` 代替触手周期；26.x 的 `oldTentacleMovement/tentacleMovement` 才对应原字段 | **确定数学错误，未运行 1.x 客户端**：同输入代表帧根触手角差约 29.12°，样本四元数分量差最高约 0.50；身体角度不应改变周期。`squid-math.csv` 的 `LegacySquidController`；两个 1.x 同名类 `:27`。不能把 26.3 正确结果外推到这两个副本 |
| F-03 | 玩家游泳触发、水下根高度和观察方向发生改变。原版入水即选游泳；当前必须 `isVisuallySwimming`。完全水下前进时 `globalOffset.Y` 从 14 变 8，并加入身体中心俯仰 | **确定语义和数学差异，整链画面未判等价**：高度项相差 6 模型单位，即 0.375 格；中心旋转附加视角俯仰，头部反向补偿。触发改变是用户既定要求，不建议不加判断地改回旧触发。R `standard/animation/controller/PlayerController.java:105`、`bit/biped/SwimmingAnimationBit.java:130`；`player-flags-math.csv` 的 `moving-underwater/view-up/view-down`；`Comparisons/player-swim.png` 正面明显不同，但混有两代原生相机差异，不能仅凭它认定旋转几次 |
| F-04 | 26.x 潜行披风删去了原版额外 25° 和 4/16 格 Y 平移 | **确定公式差异，实际披风外观未完成配对**：普通状态数学相同，潜行角度明确不同。原版本就把披风接在 body 下，不能仅以“已继承躯干”证明删去补偿必然正确。U `CapeAnimationBit.java:47`、`LayerCustomCape.java:49`；R `standard/data/PlayerData.java:42`、`:47`；`cape-math.csv`。需要完整父链证明后决定补偿，不直接盲加回去 |
| F-05 | 26.x 鱿鱼触手根从原版 MoBends 的半径 4、Y=16 改为半径 5、Y=15，同步时另乘 1.25、Y 减 1 | **确定几何差异、静态可见**：触手根向外 25%，向上 1/16 格。两代 Minecraft 原生鱿鱼本来都为 5/15，故不是新版新增 API 差异强迫的变动，属于**自创、无原版 MoBends 依据**。`Comparisons/squid.png`；U `SquidMutator.java:67`；R 同类 `:58`、`:111`。水下动态仍未知 |
| F-06 | 26.x 幼年僵尸、幼年僵尸猪灵和幼年狼采用新版专用几何，不是旧版成年网格缩小 | **外形差异明显，有新版原生依据**：头身比例、腿长、纹理和尾巴结构不同。分段膝肘、空鬃毛锚点、位移乘 0.5 等是移植版**自创适配**，不是原版幼年动画资源。`Comparisons/baby-zombie.png`、`baby-pigzombie.png`、`baby-wolf.png`；模型表给出依据。不能把“长得不同”本身直接当 bug，也不能宣称原版外观完全复刻 |
| F-07 | 原僵尸猪人映射到新版僵尸猪灵，新版头部、鼻子、耳朵不同 | **明确外形差异，有新版原生依据**；成年待机与步行动作叶子保留。`Comparisons/pigzombie.png`；R `PigZombieMutator.java`。保留新原生外形或复刻旧猪人外形是产品选择，本轮不裁决 |
| F-08 | 26.x 蜘蛛根变换从原版通用 renderer 的实体中心夹层改为 Mutator 内绕 Y=15/16 的模型中心旋转，爬墙时手工消除 yaw 再旋转 -90° | **确定实现差异，爬墙结果未知**；地面静态没有发现倒置。`creature-math.csv` 仅证明动作叶子与 IK，不证明整条爬墙矩阵。R `SpiderRenderer.java:14` 和 `SpiderMutator.java:170`。renderer 确实覆盖了基类，不能误报为必然重复应用两次 |
| F-09 | 1.x 远端剑连击以 tick/6 估算动作，26.x 按攻击事件推进；现代物品增加原版姿势映射，旋转攻击可配置关闭 | **条件性跨端分歧/明确扩展**，不属于同样输入下的普通四肢算法错误。`item-action-math.csv` 的 `spin-disabled` 明确改变轨迹发射次数；多人远端事件未实测。R `standard/animation/bit/biped/item/SwordAction.java` 与各 Target 差异清单 |
| F-10 | 26.x 延迟渲染的盔甲默认桥主要直连 Tier1；1.x 的 provider/Facade/Tier2 路径不能由其源码存在推定在 26.x 同样被调用 | **覆盖差异，具体模组装备外观未知**。普通形状不代表任意 mod 盔甲、幼年盔甲和鞘翅组合通过。R `neoforge/client/render/MoBendsRenderState.java:29`、`:79`；`ArmorRenderingFacade.java:62`。没有新增兼容或删掉现有路径 |
| F-11 | 睡眠清空动作层后，攻击类型缓存不清空；醒来持同一种武器可能不重建动作层 | **可达源码风险，原版已存在**，不是新增保真偏差。R `BipedActionController.java:234`；U 同类 `:172`；两侧 PlayerController 都在睡眠时调用。没有原生睡眠—醒来配对，不能说当前已经修复或本轮已复现画面 |

F-02 的角差由同帧两侧单位四元数的绝对点积计算，代表值不是 CSV 行数。F-03、F-04 的数值属于动作/变换项，不声称最终世界坐标简单等于该数值；根、身体、原生 renderer 和观察相机还需合成。

### 固定姿态逐项结论

### 模板需求

**现象**：相邻 Target 保留大量相同但依赖 Minecraft 类型的产品类。鱿鱼字段修正在 26.x 副本正确，在两个 1.x 副本仍错，形成真实漂移。纯 Java 组件能承载数学，却不能直接承载这些依赖游戏类型的适配逻辑；把它们强移入无游戏依赖组件会改变公开 API 或造成不正确的抽象。

**需要的表达方式**：由模板明确提供可维护的多版本 Minecraft 相关源码复用/生成机制及原生差异出口，仍保留每个 Target 独立编译、元数据和产物检查。不是要求项目私自引入预处理器、把整类塞入大段条件注释或向旧 API 加假实现。

**受影响项目**：本次直接证据为 MoBends，尤其数据、动作控制器和模型适配类；GLASS 等多版本项目是否采用，需各项目另行确认。本 Goal 不改模板，不把这条需求写成已经支持的能力。

## 结论

### 最优先的五个修复方向

1. **F-01 洞穴蜘蛛**：在自建几何与 renderer 边界正确承接每版本原生缩放，确保只应用一次。普通蜘蛛与洞穴蜘蛛成对回归，不改命中箱或物理来补视觉。
2. **F-02 两个 1.x 鱿鱼**：明确映射触手周期而非身体角度；用“相同周期、不同俯仰”和“相同俯仰、不同周期”独立样本保护语义，防止四份副本再次漂移。
3. **F-03 游泳整链**：保留用户规定的现代游泳触发，把实体物理姿态、原生 renderer 根、MoBends 根、头部观察补偿、手持物与轨迹放在一张坐标链中证明；对进出水和抬头低头做短序列，而不是仅调某个高度常量。没有核实到所谓官方 1.16 泳姿来源，不能据此为当前补偿背书。
4. **F-04 潜行披风**：用真实披风固定纹理，先合成原生潜行偏移、body 父链、25° 与 4/16 平移，再决定保留哪一项；站立、移动、潜行切换和鞘翅分别验证。当前只证明删去的项，不证明盲目加回一定正确。
5. **F-05 鱿鱼触手锚点**：若目标确实是原版 MoBends 外观，保持其 4/16 自建锚点，不把两代都存在的原生 5/15 当作被迫适配；在水下侧面和斜面短序列检查根部接缝与全长。

### 仍不能作出的声明

本轮不是“所有动画已经通过”的验收。未完成完整玩家三机位动态配对、真实披风配对、全套原生骑乘/睡眠/受击序列、狼 KUMO 全图数值执行、任意模组盔甲、幼年盔甲、所有第一人称和透明轨迹组合、四个非参考 Target 的客户端回归。逐格未知的原因在表中保留，没有拿没有测试的场景冒充一致。

原版与移植的正常保存退出、世界隔离、MCP 身份和原生 framebuffer 有独立证据；这些只能说明审查工具可用，不能代替动作保真。产品源码没有改动；检查点之后新增内容仅为审查输入登记、隔离验证配置和本报告，未再次提交或推送。

### 本轮验证结果

- 真实参考端验证运行正常结束，最后一轮 `modern-player-run.log` 记录 Gradle 成功和 configuration cache 复用；原版进程也记录保存世界与正常退出。所有运行均为隔离世界，未启动用户日常实例。
- 本报告与验证说明单独运行 rumdl 成功；根任务的 Markdown 检查也完成，`git diff --check` 通过。
- 尝试根 `spotlessApply lintMarkdown verifyConfiguration verifyCompliance`：配置与 Markdown 阶段已执行，严格合规报告原有 P-04 失败和 78 个 T-07 提示；另有格式任务在遍历文件树，读取线程栈后有界中止本次组合命令。没有将它写成全门禁成功，也没有为相同失败再次重跑或修改模板。产品源码哈希与检查点一致。
- 既有 JVM 套件不因新增审查数据整体重跑；本轮直接执行的是外部原版/移植数学夹具和原生画面观察，不把旧测试数量当作保真证据。
- 无效、受污染或已被有效样本替代的自有 PNG 送入回收站，哈希和原因见 `recycled-invalid-captures.json`；有效原生图、比较图及来源哈希保留。

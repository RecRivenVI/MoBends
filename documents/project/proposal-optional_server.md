# 模板需求：客户端独立使用与可选服务端增强

MoBends 需要在保持客户端独立使用的同时，允许已安装模组的服务端提供可选策略。目前采用 `mod_side=client`，并保留 Fabric 的 `environment="*"` 及公共初始化入口；这是用户确认的临时偏差，不修改模板文件，也不改成严格客户端模组。

## 现象

模板 2.0.2 的运行端事实只支持 `both`、`client` 和 `server`。

| 设置 | 当前模板含义 | MoBends 的问题 |
| --- | --- | --- |
| `client` | 客户端独立使用，Fabric 元数据展开为 `environment="client"` | 独立服务端不会加载已有策略同步入口 |
| `both` | 客户端与服务端都必须安装 | 不能准确表达无 MoBends 服务端同样允许客户端加入 |
| `server` | 服务端模组，可用原版客户端加入 | 不能准确表达主要功能由客户端提供 |

MoBends 当前保留三布尔策略的可选服务端发送与客户端接收。客户端可加入没有安装 MoBends 的服务器；未安装客户端的连接也不应仅因缺少可选策略通道而被拒绝。更换构建结构不应删除这些行为。

## 需要的表达方式

需要一项原生配置能够同时表达以下事实，名称由模板维护者决定：

1. 主要产品功能在客户端，客户端安装不要求服务端同时安装。
2. 模组在服务端可选安装；安装时加载公共初始化与策略功能，不加载客户端类。
3. 服务端安装不要求所有客户端安装；网络负载按可选通道协商，缺少通道时保持现有默认行为。
4. Fabric 元数据允许双端发现；Forge 使用可选端匹配；NeoForge 保留可选网络声明。
5. 文档、元数据展开与严格合规检查理解相同语义，不要求项目通过字面值覆盖来保留功能。

可以扩充 `mod_side` 的语义，也可以把“主要运行端”与“是否提供可选的另一端增强”分为两项。单纯放宽 P-04 而不定义运行行为不足以解决问题。

## 当前偏差

`gradle.properties` 仍写 `mod_side=client`，这是与客户端独立使用最接近的已有设置。Fabric `fabric.mod.json` 的 `environment` 暂保留字面值 `"*"`；公共入口保留在 `src/main`，客户端实现移入 `src/client`，避免服务端解析客户端类。

这会被现有 P-04 判为没有使用 `${fabric_environment}`。本项目没有修改模板文件、检查器或其哈希清单；不将该项失败宣称为严格合规通过。获得模板原生支持后再移除临时偏差。

## 受影响的项目

已确认受影响：`RecRivenVI/MoBends`，当前五个 Target 都保留可选策略；Fabric 的元数据展开最直接受到限制，跨 Loader 的事实与文档语义也需要一致。

其他可能存在“客户端功能加可选服务端增强”的项目需要各自确认，本需求不代替 GLASS 或其他仓库作产品决定。

## 验收要求

模板新增的表达通过配置、元数据和合规测试；真实连接分别验证客户端单独安装、服务端可选安装、双方安装和另一端没有安装的情况。原版或未装模组的一端不因可选通道而被拒绝；服务端初始化不解析客户端类。
